# Local Context Engine v1.0.0

**Release draft — unreleased.** Available binaries remain v0.2.0. No v1.0.0
artifact, platform certification or new compatibility guarantee is announced.

## Why it exists

Local Context Engine brings files, applications, processes, services and windows
into one explainable local query on Windows. It indexes file names, paths and
metadata without uploading source or requiring a cloud account or model.

## Capabilities

Stable workflows include the query DSL, English/Chinese rule-based compilation,
CLI/MCP access, deterministic ranking for fixed inputs and provider snapshots,
and selective extension/prefix/trigram planning with authoritative verification.
Index health and explanations help distinguish an empty result from unavailable
or stale data. Optional NTFS MFT/USN service deployment and desktop acceptance
across machines remain Experimental. Full-text and semantic retrieval are Future.

## Validation and performance

The existing million-record probe matches every ordered result to the linear
reference for all eight queries. Recorded accelerator construction time changed
from 11.93 s to 8.91 s; construction process peak working set changed from
1005.25 MB to 258.98 MB. Retained accelerator estimates stayed at 75.80 MB.
Common `report` latency did not improve. These Windows/Rust 1.98.1 synthetic
observations are not end-to-end or universal latency promises, and hardware
provenance is incomplete. Regression tests cover mutations, persistence and
query correctness; final v1.0.0 artifacts still require release validation.

## Security and limitations

Broad/short/fuzzy queries can still scan. Live providers depend on permissions
and changing system state. The optional elevated MFT service can expose file
names that an ordinary directory walk cannot list; normal file-content access
checks remain in force. Local indexes and usage data are sensitive. Desktop
build success alone does not establish working rendering on every machine.

The project remains independent, offline-first and MPL-2.0 licensed. No new
runtime dependency, core logic or protocol change is part of this documentation
preparation. Desktop license metadata alignment, version alignment,
minimum-toolchain validation, complete benchmark
environment capture and final installer/service smoke tests remain release gates.
